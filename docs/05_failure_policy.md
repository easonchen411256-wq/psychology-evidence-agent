# 失败处理政策

- 输入仅含题目或不完整摘要：只输出可确认的元信息，不能推断结果。
- 方法或结果缺失：标记材料不完整，并列出缺失部分。
- 发现矛盾信息：分别记录，不自行选择其中一个版本。
- 无法解析表格、图片或扫描件：说明限制，并请求可检索文本或人工核对。
- 引用信息不完整：保留已知字段，禁止补造 DOI、期刊页码或作者信息。
- 模型返回的内容不符合 schema 或未通过本地规则：不写入输出文件，并显示校验失败原因。
- Codex CLI 未安装、未登录或运行失败：不把论文内容写入日志；只返回可操作的错误摘要。
- OpenAlex 检索失败或返回不完整元数据：保留成功查询的结果与失败原因，不把空结果解释为“没有相关论文”。
- 初筛仅基于标题和摘要：任何 `direct` 标签仍需人工阅读全文后确认。
- 证据卡汇总时出现无效 JSON 或缺少必要字段的文件：跳过该文件并写入 `skipped_files`，不补写任何研究信息。
- 汇总中的证据角色仅为候选判断：材料不完整、关键词不足或存在人工核对项时，标记为 `review_required`，不输出为已确认的直接证据。
- 批量处理时某一篇文件不可读、超长、Codex CLI 失败或未通过本地校验：记录该文件的简短错误后继续处理下一篇，不将失败论文写成证据卡。
- PDF 无可提取文字、被密码保护或解析失败：不将空文本交给模型；提示用户使用可检索 PDF、OCR 后的文本或人工核对。
- 开放获取查询或下载失败：保留已获得的候选清单和单篇失败原因；不将失败解释为论文不存在或无全文，也不尝试绕过访问限制。
- 综述初稿中的来源证据卡不在输入集合、字段不符合 schema 或内容无法通过来源核对：不写入初稿文件。证据卡不足时，允许输出“直接证据有限”的范围说明，但不得补写具体研究结论。
- 批量输入的不同子目录出现同名论文文件：保留相对目录生成不同的证据卡输出路径，不覆盖先前结果。
- 开放 PDF 下载请求即使失败也写入下载报告，记录论文、链接和失败原因；只有实际写入完整 PDF 后才标记为成功。
