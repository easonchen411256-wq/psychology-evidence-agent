# 评估计划

## 目的

验证 Agent 能否正确整理心理学研究证据、控制推论强度、保留可追溯性，并诚实报告不确定性。评测区分代码级离线回归与下一阶段真实用户验证。

## 当前离线回归范围

- 证据卡 JSON Schema：必填字段、字段类型、未知字段与嵌套结构。
- 推论边界：横断面相关研究不得写成因果或干预效果；材料不完整时必须保留人工核对项。
- Codex CLI：以只读模式启动、传入严格 Schema、正确读取最终 JSON，并对错误摘要脱敏。
- 检索与初筛：OpenAlex 元数据解析、去重、未筛候选保留、筛选选择策略与输出结构。
- 全文获取：开放 PDF 判断、授权人工队列、下载失败记录与不绕过访问限制。
- 输入与输出：PDF/文本输入、批量证据卡、证据矩阵、Word 人工审查报告和综述初稿的来源约束。

## 固定测试集

- 横断面相关研究。
- 纵向观察研究。
- 随机对照试验。
- 只提供摘要或信息不完整的材料。
- 结果与结论可能被误读的材料。
- 不存在、缺失或无法确认 DOI/全文的元数据条目。
- 图表、扫描版或复杂版式导致文本提取不可靠的 PDF。

## 通过条件与红线

- 每个样例不得出现虚构论文、作者、DOI、样本、统计结果或研究发现。
- 不得出现研究设计—结论错配。
- 不确定内容必须被正确标记并进入人工核对环节。
- 综述草稿的事实性主张必须能绑定到具体 evidence card、finding 和 evidence location。
- 任一虚构信息或过度推论均视为回归失败，阻止发布。

## 运行与回归

修改 Prompt、Schema、检索逻辑、开放全文逻辑或证据规则后，运行：

```powershell
py -3 -m unittest discover -s tests
```

新出现的幻觉、错误归类或来源错配案例必须加入 `evals/test_cases.json`，修复后先复测该案例，再运行完整测试集。

## 真实模型与用户验证

- 真实模型测试只使用短小、公开或脱敏材料，并单独记录人工复核结果。
- 下一阶段邀请少量心理学学生或研究者完成完整工作流，记录从检索到审查报告的耗时、人工修订量、任务完成率和可追溯性。
- 外部数据源的实时访问策略与结果会变化，应在每次实测中记录日期、配置、命令、候选数和失败原因。
